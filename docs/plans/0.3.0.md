## Why
After [0.2.1](0.2.1.md), QAMaster builds and publishes test cases. But nothing yet checks a code change against them: there's no `src/gate/`, no runner, no automation and no push hook. 0.3.0 closes the product's [core loop](../product.md#core-loop) end to end. It also runs the cases the tester generated for Juice Shop, through playwright-bdd scripts drafted at the moment a change needs them.

## The flow it builds

```
code change (push hook or /qamaster:check)
 1. plan      the cases the diff touches (path, smoke, groups, DSM impact)              qam plan
 2. automate  per selected case, through the Framework seam (Q39):
                no script → draft   code it covers changed → update   current → keep
              then the script gate                                                      qam check-scripts
 3. show      the cases and their scripts (new / updated / kept, with diffs)
 4. approve   one yes covers both, bound to HEAD, the QA project commit and the
              hash of the drafted scripts                                               qam approve
 5. run       the Runner seam, picked per case from its link prefix (Q38)               qam run
 6. verdict   pass / fail / blocked; "new script failed" labelled; Not run (manual) listed
```

The push hook only runs step 1's fast check (Q14). When there's no approved, passing verdict for HEAD, it blocks with "run `/qamaster:check`". Drafting happens there, in the session.
