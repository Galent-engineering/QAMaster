## Why
The fastapi-react-app run (0.4.3) showed the gate can't be trusted yet:
- The push hook never blocked (R25), because the gate kept its state in the app clone and setup recorded the hook in the QA project (R22).
- A case passed while the backend answered 500 (R26).
- A second run on the same commit erased the first verdict (R28).
- Every new plan forgot the scripts already recorded, so it selected 0 automated cases until `automate --done` ran again (A15, W16, W19, R25).

The product's Trust criterion says the check is never green when something went wrong. This release makes that true for the gate.

New behaviour, a new settings key (Q53's allow-list) and a new place for the gate's files, so this is a minor release (Q46).

## Before you start
- **Moving existing state (item 1, decided r2):** read both places for one release and write only to the QA project; doctor names the old folder so it can be deleted by hand. QAMaster never deletes it.
- **The allow-list key (item 4, decided r2):** `gate.allowErrors` in `config/qamaster.json`, a list of strings matched against the URL or the error message.
- **Q50 stays proposed.** Nothing here depends on it; it's 0.8.0.
