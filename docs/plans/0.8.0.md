## Why
The 0.7.1 walkthrough on TodoApp found that a PASS could say less than it seemed: a plan that ran 0 cases passed (D3), a 500 from the API went unwatched (D16), the story in the commit played no part (D17), and a chat "yes" recorded a review (D10). The crawl also missed what TestGen needed: the edit screen behind hover-only cards (D4), limits that live in form code (D5), and shared files tagged as every screen's own (D8). Each fix changes what a user sees or is refused, so Q46 puts them in a minor release. [Q58](../decisions.md) records the decisions and amends Q54's road: 0.7.2 → **0.8.0** → its patch → 1.0.0.

## Items
Each is built test-first against fakes. Four groups own separate files and are built in parallel on their own branches, then replayed onto `release/0.8.0` in the order gate, framework, store, dsm. `shared/models.mts` and `shared/schema.mts` take only additive optional fields, each group in its own type; the replay resolves any import-line conflicts.

## Known interactions
- **D8 and D3 together:** after item 18 a change to shared auth code selects smoke plus DSM impact (Q37). If the smoke case is manual, the plan matches only manual smoke, which item 1 keeps as a pass with a warning. Item 5 (stories) and DSM impact are what select more; the next walkthrough checks an auth change.
- **`check --yes`** now carries three meanings to keep straight in `check.md`: approve and run (today), consent with no terminal (item 2), and with `--allow-empty` (item 1) an empty approval. Claude passes `--allow-empty` only on the person's own words.
- **Existing automation folders** (TodoApp): item 9 replaces `app-errors.ts`; items 10 and 11 add files and `check-scripts` findings rather than editing `fixtures.ts` or the user's steps.

## Not in 0.8.0
- `{len:N}` (D15): backlog; the 0.7.2 docs workaround stays.
- A gate-level reset command (`gate.beforeRun`): backlog.
- `required` from form code (D5's follow-up), Python imports in the scan (D8's backend half), ADO Tested By links for stories, per-field merge after `--take-store`, the reviewer identity as ADO account plus git email (Q12 drift): backlog.
- Still undecided, not in this release: whether publish without `--to` always writes the file store too; whether a push from the QA project itself is exempt from the hook.
