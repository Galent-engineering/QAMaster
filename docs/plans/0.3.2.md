## What went well

- **The Toolshop run was the right test.** It was the first app none of the demos had used, and it found five real defects in an hour. All five were small once the logs and the code were read together.
- **The 0.3.1 fixes held up on a real app, with Azure DevOps.** Republishing changed nothing (the 0.2.2 description fix), scripts were kept once published (the 0.3.0 case-hash fix), and doctor named the runner, the browser and the app URL (F4). A monorepo subfolder worked as the code source.
- **Every issue arrived with evidence.** The crawl log, `dsm/state.json`, the code model and the templates pointed at the cause each time, so the fixes were written in a few lines.
- **The clean-room Docker run (0.3.1) paid for itself.** Its 11 prerequisite findings are why a fresh machine now gets a message with the command, not a failed test.
- **Test-first kept the fixes small.** Each of T1–T5 was a failing test first, and the tests use the real shape of Toolshop's data.
