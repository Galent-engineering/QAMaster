## Why
The fastapi-react-app run (0.4.3) was the first app where every page but two needs a session, and QAMaster covered one module of six:
- The crawl signs in first, so `/login` and `/register`, the two public forms, have no elements (R5). Login and Register got no test cases (R12).
- The add and edit dialogs are recorded, but not their fields (R6), so Todo got no add, edit or length-limit case, the module's core rules (R12).
- Clickable cards and sidebar links aren't followed or clickable (R7, R8); two crawls can't be kept side by side (R9).
- Each screen's "source files" are the auth plumbing, not its own components (R10), so every case got 7–9 path tags and a change to `axios.ts` selects all of them (R16).
- Every screen is labelled `Vite + React + TS` (R30).

The crawl is also slow: one page at a time, a fixed 1.2 s wait plus up to 10 s of network idle per page (S2–S4, S7). TestGen's `.feature` text and the automation's steps don't share wording, so every scenario is rewritten (W11). Q31's presets and model setting are still unbuilt. And the API and Mobile Web channels (product v1, Q54) have no scripts: Q48 already keeps API routes out of the screen matrix "until the API channel".

New behaviour, new keys, flags and a subcommand, so this is a minor release (Q46). Fixes found by its rehearsal go to 0.7.1.

## The DSM shape this release adds
The two tracks build at the same time, so `dsm` produces and `gen` consumes this shape. Every field is optional, so a DSM from 0.6.0 still reads:
- **Screen (`PageNode`):** `access?: 'public' | 'signed-in' | 'both'`. `label` may now be a heading (item 7); `id` is still the route.
- **Form:** `dialog?: string` when the form sits in a dialog (its `name` is then the dialog's title).
- **Field:** `min_length?`, `max_length?`, `min?`, `max?`, `pattern?` (each `null` or absent when the page declares none).
- **Elements:** sidebar links are `link` elements on each page that shows them; a card's click is a relation of type `click`.

`gen` writes its own DSM fixtures with these fields and reads them through local types until both tracks merge; the integrator then folds the types into `dsm/build.mts`'s `PageNode`.

- Sidebar items with no `href` are only recorded when a click navigates, within `explore_clicks.max_per_page`: the item for the current page isn't an element of that page.
- Cards and sidebar items are found by `cursor: pointer`; a clickable element without it is missed.
- The `session` field of a case isn't rendered into the `.feature`; a signed-in case's sign-in rests on its preconditions.
- A step that leads to a route renders as `the URL should contain "<route>"`, so that step's own expected text is only in `testcases.md`, the CSV and the published steps. Two cases whose steps now render alike merge into one Scenario Outline.
- API cases are found by channel `API` only; a case with `dsm:api:` evidence on another channel is checked as a screen case.
- `check-scripts` misses an API step that renames the `request` fixture (`({ request: ctx })`).
- `Selection:` names the groups model under `standard` with AI on even in CI, where no model picks groups.
- Already there before 0.7.0: the code scan reads any `src/pages/` folder as Next.js pages, so a CRA or Vite app with `src/pages/` gets wrong routes.
