## Why
Step 6 of the demo path is the one still not built. Without it TestGen can't cite a requirement (`req:` evidence needs `requirements/<scope>/requirements.json`, and today the TestGen skill says to leave requirements out), so test cases trace to screens and code but never to a story, and the reports have no requirement to trace to.

The ADO side is mostly there: `AdoRequirements` (`adapters/ado.mts`) reads a sprint, the current sprint or a date range, works out which work item types are requirements in the project's process, and falls back to every non-test item when it can't. What's missing is the command, the file it writes, and the pipeline, skill and report wiring. Autonomous-QE's `tools/requirements/requirements.mts` (252 lines) is the source to port; it went through MCP, and QAMaster reads ADO over REST instead (Q5).

A new command, so this is a minor release (Q46).
