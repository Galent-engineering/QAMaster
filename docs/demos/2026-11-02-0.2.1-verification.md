# QAMaster 0.2.1 verification: feedback

Claude tested the installed 0.2.1 build (`~/claude-plugins/qamaster`, `qam 0.2.1`) against the real 0.2.0 walkthrough project on 2026-11-02. No plugin code was changed during the test.

**How it was run**
- Scratch copies of `~/Downloads/DemoTestv0.2.1` (app `JuiceShopOnline`, 4 runs, 243 cases), without `sources/` and `node_modules/` (`sources/` was symlinked). The original folder was only read.
- **ADO copy:** read-only. `qam doctor`, plus `qam publish <run> --refresh` dry runs against `sarvagyameel/JuiceShopOnline`. **Nothing was written to ADO.**
- **File-store copy:** `QAMASTER_STORE=file` and no ledger. Used for everything that applies: smoke across runs, conflict `--apply` and retire.
- **A1:** checked with headless Claude sessions (`claude -p`) in a copy, with the plugin loaded from its project settings.
- The scratch copies, including a copy of `.env`, were deleted afterwards.

## Edge cases seen (behaviour is by design or minor)

- **A5:** each dry run still shows only its own run. Four previews in a row each say "the plan has 0 smoke", so together they promise 38 again. The cap is enforced only at apply, which does refuse and explain. Enhancement E1 covers this.
- **A5:** `--skip-smoke` isn't remembered. Two cases unticked in CatalogEngagement come back on every later dry run as "2 more cases match … weren't offered". Only removing smoke in the store is remembered (Q8).
- **A5:** in a refusal, the "N more cases … weren't offered: full" line is printed before the "Smoke changed since the dry run" line. Putting the refusal first would read better.
- **A5:** applying with `--skip-smoke` for exactly the cases that no longer fit goes through without a new dry run. That's correct, because the person unticked them explicitly.
- **A2:** with no `app.name`, the message says "named like the app ('ado')", but 'ado' is the folder name. Saying "the app (folder name)" would be clearer.
- **A3:** running setup again with a different `--app` adds a second integration (`claude-hooks:JuiceShopOnline` and `claude-hooks:ShopRenamed`). The old one stays recorded.
- **A7:** an empty or accidental `testcases.json` blocks too, which is intended. The message names both files.
- **Retire:** a case the validator needs, such as the only E2E case for Search, can't be removed from a run, because validation fails with a coverage gap first. That's correct, but a team retiring a case has to add a coverage exclusion first. The Publish skill doesn't say so.
- **`qam review` (the CLI) asks nothing.** A1's protection is in the skills. Anyone, or any session, calling the CLI records a review at once. It's acceptable while commands are the only front end.
- **Pipeline status after switching stores:** in the file-store copy, Publish showed "done, 4 published runs" from the old ADO `published.json` files, though one run was never applied to the file store. It also stays "done" while a conflict is held back.
