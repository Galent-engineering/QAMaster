# QAMaster 0.3.0 in a clean Docker container: test report

Claude ran this on 2026-11-02, from the release zip `dist/qamaster-0.3.0.zip`. It repeats the flows of the [Mac run](2026-11-02-0.3.0-end-to-end.md) on a machine with nothing installed, to find every prerequisite QAMaster assumes. Plan: [0.3.0 r9](../plans/0.3.0.md).

- **Machine:** `node:24-bookworm-slim` (Node 24.22.2, npm 11.19.1, arm64), running as the image's `node` user. Each tool was added only after QAMaster first failed without it.
- **No ADO writes.** `QAMASTER_STORE=file` throughout.
- **No pushes outside the container.** Remotes were bare repos inside it.
- `CheckMasterDemo`, `juice-shop` and `DemoTestv0.2.1` were mounted read-only and cloned or copied inside the container. `.env`, `node_modules` and `sources/` weren't copied from the QA project.
- **Not run in the container:** Claude Code, which can't sign in there. The `qam` CLI and the push hook were run directly, the hook fed a `PreToolUse` event on stdin. `claude plugin validate` passed on the unzipped release, on the host.

**Reproduce it:** `scripts/docker-e2e/run.sh [zip]`. It builds [the Dockerfile](../../scripts/docker-e2e/Dockerfile), which holds every prerequisite found, and starts Juice Shop on a shared network. Then [inside.sh](../../scripts/docker-e2e/inside.sh) runs both paths. Each step states the exit code 0.3.0 gives today. The missing-tool steps hide git or uv from `PATH`. The script removes its containers, network and temporary files when it ends.

## Edge cases seen (by design or minor)

- `qam setup` in a pytest-only repo still writes a `package.json` with "Playwright 1.64.1 for the crawl".
- `qam setup` without git still creates the config and the project link before it stops. A re-run after installing git continues.
- The app repo's `.env` carries the QA settings. The source check reported it as "uncommitted changes", which reads like a problem with the code.
- The pytest and Node Playwright both pinned 1.64.1, so they shared one Chromium download. A different pin would mean two browsers.
- Juice Shop's URL had to be the container's name on the Docker network. Inside the test container `localhost` is the container itself (F2's unreachable-app row).

## Not tested

- **Node older than 24.** `qam setup` checks for 24, but Node 22 before 22.18 can't load `.mts` files at all, so the check would never run. Testing it needs another base image (about 80 MB).
- **Claude Code in the container**: `/qamaster:check`, the hook firing from a real `git push` through Claude, and the AutomationCode skill. The hook script was run directly.
- **x86_64.** The run was on arm64 (Docker Desktop on Apple silicon).
- **The DSM crawl and TestGen** on a clean machine: out of scope for 0.3.0's gate.
- **Azure DevOps.** The file store stood in, as asked.
