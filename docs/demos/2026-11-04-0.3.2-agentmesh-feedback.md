## Not a QAMaster bug

- **The spend limit** stopped the session overnight, from 07:27 on 2026-11-03 to 04:38 on 2026-11-04 ("You've hit your individual spend limit"). It's an account limit. A10 made the run use more of it.
- **The agent wouldn't read `cloud-creds` or edit `.env`.** That's the rule ("No secrets in the plugin", and the ADO skill), and the repo's `.claude/settings.json` denies the reads too. It cost a few round trips, which A1 and A2 made worse.
- **`qam dsm` with no subcommand** blocked with "Use qam dsm run, refresh, changes, impact, scan, build, render." The `/qamaster:dsm` command tells the agent to pick `run` or `refresh`. The agent skipped that, then ran `dsm run` straight after.
- **Moving the ledger aside by hand** (`mv ledger.json ledger.file-store.bak.json`). It's what the block message says to do. The file store's CSV and the ADO project now both hold the 62 cases. That's expected after a switch, not a duplicate in one store.
- **The domain.** No domain sub-skill fits a multi-agent runtime. The agent classified it as AI/ML + API + Web, which the router allows.
- **The spend limit stopped the forked script writer** once more (06:19, resumed at 07:19 after you raised the limit). Account limit, not QAMaster.
- **The 403 on `git push`.** `smeel19` has no write access to `Sarvagya-meel/agentmesh`. You chose to stay local, and the agent saved that as a memory in the agentmesh project. QAMaster's part is A15.
- **Docker Desktop wasn't running** and the compose stack had to be started. AgentMesh's own setup, outside QAMaster.
- **2 unit tests of AgentMesh fail** (`test_google_adk_agent.py`: `NameError: name 'StaticPool' is not defined` in `google/adk/sessions/database_session_service.py`). A bug in the google-adk library, shown by the app's own `merge_gate.py`, not by QAMaster.
- **The auto-mode classifier blocked an ADO write** until you replied. Claude Code's rule, and the right one: Azure DevOps writes need your yes.

## Proposed decision (not written to `decisions.md`)

**Q49 (proposed). A QA project with no push access can still gate its scripts, and says so.** Today a script is linked to its test case only once its commit is pushed (Q39, Q40), so a local-only QA project gets no links and the gate selects nothing (A15). Options: (a) keep the rule and make the message name `qam automate <plan> --done` (0.4.1, no decision needed); (b) let a file-store project link local scripts with the repo-relative path and the commit, no web address (a new setting or flag, so a minor release); (c) both. I'd take (a) now and decide (b) after the 0.5.0 requirements work.
