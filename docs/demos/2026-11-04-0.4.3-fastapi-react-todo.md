# 0.4.3 on fastapi-react-app: a signed-in React SPA with a FastAPI backend

- **Date:** 2026-11-04
- **Build:** 0.4.3, loaded from this checkout (`plugin/`); the CLI run from the QA project's launcher and, for the gate, from `plugin/src/cli/main.mts`
- **App:** [finsberg/fastapi-react-app](https://github.com/finsberg/fastapi-react-app) @ `988115c`: a todo list with sign-up and sign-in. React 18 + Vite + Chakra UI at `http://localhost:5173`, FastAPI + SQLModel + SQLite at `http://localhost:8000/api/v1`, 9 backend pytest tests. 816 KB
- **QA project:** `../fastapi-react-app-qa`, the clone inside it. Raw run log: its `FINDINGS-log.md`
- **Store:** local file (`testcases/testcases.csv`) first, then Azure DevOps (`sarvagyameel/fastapi-react-app`, plan `TodoApp`, cases 409–413)
- **Why this app:** it's small and has real tests, and it covers what earlier demos didn't: an SPA where every page but sign-in and sign-up needs a session, modal forms, and clickable cards instead of links
- **Result:** end to end on the Todo module. 5 cases validated (3 exclusions), reviewed and published (1 smoke); 3 scripts drafted; gate plan `19cbecb1` on a one-line backend fix: PASS 3 of 3. Login and Register got no cases. 30 findings, R1–R30

## App defects found while curating (from the code, not run)

For the next run's cases once R5 and R6 are fixed:
- Sign-up accepts `isAdmin` from the request body (`backend/app/models/user_model.py:14`, `services/user_service.py:41`).
- `PUT /users/{user_id}` has no sign-in check (`api/api_v1/handlers/user.py:38-41`).
- `POST /auth/refresh` catches `jwt.JWTError`, which PyJWT doesn't define, so a bad token likely gives 500 (`api/auth/jwt.py:74`).
- `GET /todo/<missing id>` returns 500 (seen in the backend log, see R26).
- Deleting a missing todo calls `session.delete(None)` (`services/todo_service.py:73-74`). The gate's demo change fixes this on the local branch `qa-demo/delete-guard`.
- The UI and API limits differ: title 5–55 vs 1–55, description 5–200 vs 1–755, username 5–24 vs none.

## Not covered by this walkthrough

The run is complete end to end for one module, but not a full walkthrough of the build:
- **Modules:** test cases only for Todo (1 of 6 components); Login and Register can't be covered (R5, R12); Home, User and Users weren't attempted.
- **Requirements** (step 6): not built until 0.5.0.
- **The failure path:** no gate run failed, so a FAIL verdict, a retry and a flaky verdict, a BROKEN case, failure screenshots, `qam feedback` defect drafts and the defect and root-cause reports with real data were never seen. R26 shows a FAIL was due.
- **Store life cycle:** a republish that updates cases, a conflict, `--retire` and `--leave-out`.
- **DSM after the change:** `qam dsm refresh`, `changes` and `impact <files>` for the gated commit.
- **Front ends:** apart from `/qamaster:status`, the slash commands and the Design-Structure-Matrix, Publish, Gate and ADO-API skills were bypassed for direct `qam` calls, so their wording and approval prompts weren't exercised; nor were `qam check` (one shot), `qam tc`/`req`, `export` and `mcp-serve`.
