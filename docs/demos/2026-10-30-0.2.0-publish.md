## Step 0. Doctor flags the old config

**On a fresh setup (this run):** setup already writes the new defaults, so the expected result is **no** `config defaults` WARN. Record what doctor showed; the hand fixes below don't apply.

This project was set up with 0.1.0, so its config misses two newer defaults. Ask: *"Run QAMaster doctor."*

**Expected:** a `WARN  config defaults` line naming both:
- `publish.pathDepth is 3, the default is now 4`;
- `exclude lacks codefixes/`.

The WARN doesn't fail doctor. Then fix both by hand:
- in `config/qamaster.json`, set `"pathDepth": 4`;
- in `config/dsm-config.json`, add `"codefixes/"` to the juice-shop `exclude` list.

Run doctor again and the WARN is gone. Optional: *"Refresh the DSM"*, which should now find about 48 routes, not 489.

## Step 3. Dry run: read the preview

Ask Claude: *"What would publishing the Address test cases do?"* (or `/qamaster:publish`)

**Expected:** a preview headed `QAMaster publish <run> → File testcases/testcases.csv, plan … (dry run)` with **Create (n)**, each case's suite and tags, a **Smoke suggestions** list with boxes ticked, and "Reply yes to apply". Check:
- the `path:` tags point at the right folders (for Juice Shop: `frontend/src/app/address-create/**`, not `frontend/src/app/**`; your `config/qamaster.json` must say `"pathDepth": 4`);
- cases with no source link are listed under **Not linked to code**;
- **nothing was written**: no `testcases/` folder, no `.qamaster/ledger.json`.

## Step 8 (optional). Publish into a real ADO project

New in 0.2.0: QAMaster can also **create the ADO project**, after a preview and your yes.

1. **A missing project lists the real ones.** In `DemoTest1/.env`, set `QAMASTER_STORE=ado` and `QAMASTER_ADO_PROJECT=` a name that doesn't exist, e.g. `JuiceShopQA`. Keep the org and token. Ask: *"Run QAMaster doctor."*
   - **Expected:** `test case store` says the project doesn't exist, lists your existing projects (CheckMasterDemo), closest first, and offers three ways forward: pick one of them or a new name; switch to the file store; or let publish create it.
2. **Start a new ledger.** The file-store ledger belongs to the file store, and `qam publish` will block on a different store. Move `.qamaster/ledger.json` aside, and keep it, so every case is created as new.
3. **Dry run.** Ask: *"/qamaster:publish"*.
   - **Expected:** the preview starts with `The ADO project 'JuiceShopQA' doesn't exist; --apply will create it (process …, private)`, then the plan line, then the cases. Claude must say this is an organization-level change and needs the "Create new projects" permission. It must not apply anything.
4. **Say yes.**
   - **Expected:** `Created ADO project JuiceShopQA.`, then the plan, a suite per module, and one test case per draft with tags and steps.
   - Creating a project can take up to a minute.
   - If your token lacks the permission, the message names it, and nothing is half-made.
5. **Publish again.** It should say there's nothing to do.

Prefer to skip project creation? Set `QAMASTER_ADO_PROJECT=CheckMasterDemo` (or a sandbox project), then do steps 2–5. Step 3 then has no project line, only the plan.
